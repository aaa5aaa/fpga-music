# PC 蓝牙重连修复（1.0.1）

## 原因

旧版 `stop()` 在 GUI 线程最多等待后台线程 3 秒，随后 `restart()` 立即调用 `start()`。
若蓝牙仍在扫描、连接或释放 Windows GATT 资源，后台线程仍存活，`start()` 会直接返回。
这时按钮已经按下，却没有真正启动新连接。旧事件循环与发送队列引用也未清空。
旧版未设置掉线回调，空闲期间意外掉线后可能仍显示已连接。

## 修改

- 使用非阻塞停止请求取消当前扫描、连接或通信操作；GUI 不再等待线程 join。
- 在旧线程完成 GATT 释放和 asyncio 事件循环退出后，由 Qt 自动执行排队的重连。
- 重复停止请求不取消正在执行的清理工作。
- 每次连接先扫描获得新的 BLEDevice；根据已选地址重连，重新扫描时按设备名选择。
- 注册掉线通知，及时更新状态并退出旧通信任务。
- 清空旧循环、队列、客户端引用；发送时防止访问已经关闭的循环。
- 设置通信和清理超时，保留具体错误提示，不再立即用“已断开”覆盖失败原因。
- 页面显示扫描中、连接中、断开清理中等状态，并防止重复点击发起并行连接。
- 关闭窗口时先等待蓝牙清理完成，再退出程序。

已更新 Python 源码及独立 EXE。没有进行反复断开/重连的硬件测试。
如果外设仍被手机占用、未重新广播，或 Windows 蓝牙驱动未恢复，程序会显示相应连接错误。
