# LCD 实时仪表页（480×320）

当前工程使用 `src/lcd_dashboard.v`，由 `acg720_instrument.v` 实例化。
旧的 `lcd_ui.v` 不参与构建。屏幕接口、引脚、横屏方向保持原配置。

## 主页

按批准的深色、青色布局划分为状态栏、音色、音符与音量、ENV、效果状态五个区域。
文字字模保存在 ROM 中；数值、曲线、状态和选中效果均实时读取 FPGA 信号，并非静态预览图片。

| 显示 | 实际输入 |
|---|---|
| 钢琴 / 古筝 / 箫选中状态 | `timbre` |
| 播放、录音、蓝牙 | `song_playing`、`rec_active`、`bt_link` |
| 当前音符 | 最近出现上升沿的 `voice_gates` 声部，音名按 C4 起的半音编号转换 |
| 主音量数值、条形 | `vol`，范围 0～19 |
| ENV | 被跟踪声部的 `voice_level`，包含松键后的释放阶段 |
| 颤音、滑音、合唱、延迟 | 对应的实际效果控制信号 |

ENV 每 20ms 采样一次，432 列约表示最近 8.64 秒，最新数据在右侧。
默认请求约每 100ms 更新一次曲线，实际刷新频率受 SPI 和其他区域更新影响。
同时触发多个音时选择最高音；后续新音触发会切换跟踪对象。
这是一条真实采样历史，不是预先画好的 ADSR 示意曲线；钢琴、古筝的保持值为零时不会显示保持平台。

S1 切换主页和音符活动柱状图。第二页显示实际门控的 32 个音符活动，不冒充 FFT 频谱。
LCD 仅显示状态，不新增触摸操作。效果仍由现有实体按键/上位机控制。

## 刷新实现

- 静态文字：同步 1bpp ROM；动态文字：同步字模 ROM。
- 颜色、卡片、音量、开关和曲线由像素逻辑绘制。
- 数据在发送对应窗口前锁存，避免一次窗口刷新中出现数值和条形不一致。
- 主页采用轮转调度的局部刷新，连续变化的 ENV 不会阻塞音量、音符、音色或状态更新。
- ENV 使用循环历史缓冲，采样独立于 SPI 发送。
- SPI 为模式 0，50MHz 主时钟下约 12.5MHz，沿用屏幕原横屏设置。

## 同次发声修复

`synth_voice.v` 增加主时钟域触发锁存，避免短于音频采样周期的同音 off/on 被漏掉。
新的触发在下一个音频采样点重新进入 Attack，并重置包络及相位，不再等待 Release 完成。

按用户要求，本次只修改代码，未完成编译、仿真或板上验证，也未生成新的烧录文件。

## 第二页：32 声部实时监视

第二页读取全部 32 个声部的 voice_level 与 voice_gates，每次刷新前统一锁存。柱高对应实际 ADSR（不乘力度）；青色为门控开启，蓝色为释放尾音，无电平时不画有色柱。底部 19 白键、13 黑键显示同一批数据。活动数量为门控或电平非零的声部数，按下数量为门控开启数，释放数量为门控关闭但电平非零数。计数复用单个计数通路，逐声部累加。

音域 C4～G6。S1 返回主页。受 SPI 带宽限制，显示是定期刷新的快照，非常短的音符不保证每次都能显示；音频时序不受影响。该页面不是 FFT 频谱。文字只保存 120 行有效文字带的 1bpp 字模，不新增完整帧缓冲。旧 lcd_ui.v 已移除；已有历史副本未删除，也未加入构建。按用户要求未进行编译或仿真，不创建额外备份。

## 实体键形状与音高编号

底部琴键形状按工程灯带黑键掩码 0x2A52A52A 生成，与 PC 的 is_black(note) 一致。零起算黑键编号：1, 3, 5, 8, 10, 13, 15, 17, 20, 22, 25, 27, 29。这是一套 F 起始的实体黑白排列，但当前音高表仍规定 note 0=C4；显示音名表示实际声音，而不是键壳传统音名。未改动扫描顺序、音高表、曲谱编号或 PC 键盘映射。

初始音色统一为钢琴（编号1）；蓝牙 ADSR 初值为 A步进682、D步进1、S电平0、R步进4，匹配 FPGA 默认钢琴模板。第一屏和声部锁存的钢琴初值保留，PC 下拉框显式初始化为钢琴。连接后仍同步实际设备状态，不强制覆盖用户已选音色。

## 音色编号更新

FPGA 发声、数码管、LCD、蓝牙 SET_TIMBRE / LIVE_PARAMS 统一使用 1=钢琴、2=古筝、3=箫；上电默认1。PC 下拉显示编号和名称，发送编号1..3，接收后转为 Qt 的0..2下标。原0..2编码的旧PC可执行文件不能搭配此固件，需要重新打包PC源码。小程序不发送音色设置命令，无须改动。control_keys 首次采样只记录开关初始位置，不产生音色切换脉冲。
